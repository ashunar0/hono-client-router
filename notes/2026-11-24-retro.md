# クライアントルーターとは何か、どう作られているか

## クライアントルーターとは

ページを読み込み直さずに、URL と画面を切り替える仕組み。

ブラウザは本来、リンクのクリックやフォームの送信でサーバーにリクエストを送り、返ってきたページで画面をまるごと置き換える。SPA ではこの仕事をルーターが代わりにやる。サーバーには行かず、JavaScript で URL を書き換えて、画面の必要なところだけを描き直す。

## 中身は 3 つ

ルーターは、次の 3 つをつないだもの。

| 部品 | 役割 | 正体 |
|---|---|---|
| 履歴 | URL を書き換える、戻る・進むを検知する | ブラウザ標準の History API（`pushState` / `replaceState` / `popstate`） |
| マッチング | URL からどのルートかを決め、パラメータ（`:id` など）を取り出す | パスのパターン照合 |
| 描画 | ルートに対応する画面を出す | React などの描画の仕組み |

ルーター自身が新しく発明しているものはほとんどない。履歴はブラウザが、描画は UI フレームワークが持っている。ルーターの仕事は、この 2 つをマッチングでつなぐこと。

## 遷移の流れ

1. `<a>` のクリックを横取りする（`preventDefault`）。これをしないと、ブラウザが普通にページを読み込み直してしまう
2. `history.pushState` で URL を書き換える。ページは読み込み直されない
3. 新しい URL をマッチングして、対応するルートを見つける
4. 必要ならデータを取得する（loader）
5. 画面を描画する

戻る・進むのときはブラウザが `popstate` を発火するので、3 から実行する。

## 履歴の扱い

| 場面 | 使うもの | 理由 |
|---|---|---|
| リンクのクリック | `pushState` | 履歴を 1 つ積む |
| 戻る・進む | `popstate` を受けて描画だけ | その URL は既に履歴にある。ここで push すると「進む」の履歴が消える |
| リダイレクト | `replaceState` | 元の URL を履歴に残すと、戻ったときにまたリダイレクトされて戻れなくなる |

## ルーターが持っている機能

| 機能 | やっていること |
|---|---|
| loader | 描画の前にデータを取得する |
| action | フォームの送信を横取りして処理する。サーバーへの POST の代わり |
| リダイレクト | 別の URL に遷移し直す。URL は `replaceState` で書き換える |
| ガード | 条件を満たさないとき（未ログインなど）に、描画の前にリダイレクトする |
| レイアウト | 複数のルートで共通の枠（サイドバーなど）を出し、中身だけを切り替える |
| 404 | どのルートにもマッチしなかったときの画面を出す |

## 非同期の遷移とレースコンディション

loader が `await` している間に、次の遷移が始まることがある。`/users/1` → `/users/2` と素早く切り替えて 1 のデータのほうが遅く届くと、URL は 2 なのに画面が 1 で上書きされる。

`await` のたびに、その間に別の処理が割り込みうる。これが原因。

対策は、新しい遷移を始めるときに前の遷移を中断すること。

1. 遷移ごとに `AbortController` を作り、その `signal` を loader に渡す
2. loader は `signal` を `fetch` に渡す
3. 次の遷移が始まったら、前の controller を `abort()` する。中断された遷移の結果は描画しない

React Router の `request.signal`、useEffect のクリーンアップ、TanStack Query の `signal` も、同じ問題を解いている。

## 描画の分け方

### ルートは「何を出すか」を返し、描画はルーターがやる

ルートのハンドラは出すものを返すだけにして、画面への反映はルーターに任せる。こうしておくと、描画の方法を変えるときにルーターの描画部分だけを直せば済む。

### 差分描画が要る理由

遷移のたびに画面をまるごと作り直すと、レイアウトの部分まで作り直される。たとえばサイドバーの入力欄に打った文字が消える。だから変わったところだけを更新する差分描画が要る。

### フレームワークに依存しない作り（TanStack Router）

TanStack Router は、ルーターを 2 つに分けて複数のフレームワークに対応している。

- **core**：URL から matches（当たったルートと取得したデータ）を作る。描画はしない
- **adapter**（React 用、Solid 用など）：matches を受け取って描画する

マッチングとデータ取得はどのフレームワークでも同じなので、描画だけを adapter として差し替えられるようにしている。

## 本物のルーターにあって、まだ作っていないもの

- [ ] ネストしたレイアウト（親子で何段も重ねる。React Router の `<Outlet />`）
- [ ] 読み込み中の表示（pending UI）
- [ ] 型安全なリンク（存在しないパスやパラメータの間違いを型でエラーにする）
- [ ] スクロール位置の復元（戻ったときに、前に見ていた位置に戻す）
